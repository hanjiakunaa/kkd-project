## 📋 一、Vision 图片理解节点

### 功能说明

Vision 节点使用多模态大语言模型（如 GPT-4o、GLM-4V 等）来理解和分析图片内容。

### 支持的服务商

| 服务商   | 模型              | 特点           |
| -------- | ----------------- | -------------- |
| OpenAI   | GPT-4o, GPT-4o-mini | 理解能力强     |
| 智谱 AI  | GLM-4V            | 中文理解优秀   |
| 阿里通义 | Qwen-VL-Plus      | 性价比高       |
| Moonshot | Moonshot-V1       | 长上下文支持   |

### 使用示例

```javascript
// 节点配置
{
  type: 'vision-node',
  params: {
    provider: 'openai',
    model: 'gpt-4o',
    prompt: '请详细描述这张图片的内容',
    temperature: 0.7,
    maxTokens: 1000,
    detail: 'high' // auto, low, high (仅 OpenAI)
  }
}
```

### 输入格式

支持以下输入格式：
- 图片 URL：`https://example.com/image.jpg`
- Base64 编码：`data:image/jpeg;base64,/9j/4AAQ...`
- JSON 对象：`{ "url": "https://...", "prompt": "..." }`

### 典型应用场景

1. **内容审核** - 识别图片中的不当内容
2. **商品识别** - 识别商品信息和特征
3. **场景理解** - 理解图片场景和氛围
4. **辅助描述** - 为无障碍访问生成图片描述

## 📋 二、OCR 文字识别节点

### 功能说明

OCR 节点可以从图片中识别并提取文字内容，支持多种语言和输出格式。

### 支持的服务商

| 服务商   | 特点             | 支持功能       |
| -------- | ---------------- | -------------- |
| 阿里通义 | 通用识别         | 多语言         |
| 百度 OCR | 专业 OCR 引擎    | 表格识别       |
| 智谱 AI  | GLM-4V 支持      | 智能理解       |
| OpenAI   | GPT-4o 支持      | 高准确率       |

### 使用示例

```javascript
// 节点配置
{
  type: 'ocr-node',
  params: {
    provider: 'qwen',
    language: 'auto', // auto, zh, en, zh_en
    outputFormat: 'text', // text, json, markdown
    detectTable: false // 是否识别表格（百度）
  }
}
```

### 输出格式

**文本格式 (text)**
```
这是识别的文字内容
保持原有格式和排版
```

**JSON 格式 (json)**
```json
{
  "text": "完整文字内容",
  "lines": ["第一行", "第二行", "第三行"]
}
```

**Markdown 格式 (markdown)**
```markdown
## OCR 识别结果

\`\`\`
识别的文字内容
\`\`\`
```

### 典型应用场景

1. **文档数字化** - 将纸质文档转为电子文本
2. **名片识别** - 提取名片信息
3. **发票识别** - 提取发票关键信息
4. **截图文字提取** - 从截图中提取文字

## 📋 三、执行结果缓存

### 功能说明

自动缓存节点执行结果，避免重复执行相同的操作，大幅提升工作流执行效率。

### 工作原理

1. **智能缓存键** - 根据节点类型、参数和输入自动生成缓存键
2. **多级缓存** - 内存缓存 + IndexedDB 持久化
3. **自动过期** - 默认 24 小时过期，自动清理
4. **大小限制** - 最多缓存 100 个结果，超出自动清理

### 可缓存的节点类型

- ✅ LLM 文本生成
- ✅ 图片生成
- ✅ 视频生成
- ✅ 音频生成
- ✅ Vision 图片理解
- ✅ OCR 文字识别
- ✅ 文本处理

### 缓存管理

```javascript
// 启用/禁用缓存
executor.enableCache()
executor.disableCache()

// 清空缓存
await executor.clearCache()

// 获取缓存统计
const stats = await executor.getCacheStats()
console.log(stats)
// {
//   totalCount: 45,
//   memoryCount: 10,
//   dbCount: 45,
//   enabled: true
// }
```

### 性能提升

- **首次执行**：正常速度
- **缓存命中**：几乎瞬间完成（毫秒级）
- **成本节省**：避免重复调用 API，节省费用

### 缓存命中率

执行完成后会显示缓存统计：

```javascript
{
  hits: 8,      // 命中次数
  misses: 2,    // 未命中次数
  hitRate: '80%' // 命中率
}
```

## 💡 最佳实践

### Vision 节点

1. **选择合适的模型**
   - 通用场景：GPT-4o / GLM-4V
   - 中文内容：GLM-4V / Qwen-VL-Plus
   - 成本敏感：GPT-4o-mini / Qwen-VL-Plus

2. **优化提示词**
   ```javascript
   // ❌ 模糊的提示词
   prompt: "描述图片"
   
   // ✅ 明确的提示词
   prompt: "请详细描述图片中的：1. 主要物体 2. 颜色搭配 3. 构图方式 4. 整体氛围"
   ```

3. **控制输出长度**
   - 简单描述：maxTokens: 500
   - 详细分析：maxTokens: 1500
   - 报告生成：maxTokens: 3000

### OCR 节点

1. **选择合适的服务商**
   - 通用文档：阿里通义
   - 专业 OCR：百度 OCR
   - 智能理解：智谱 AI / OpenAI

2. **提高识别准确率**
   - 使用高清图片
   - 确保文字清晰可见
   - 避免过度倾斜或变形

3. **合理使用输出格式**
   - 纯文本提取：`text`
   - 结构化处理：`json`
   - 文档生成：`markdown`

### 缓存使用

1. **适合缓存的场景**
   - 批量处理相同内容
   - 开发调试阶段
   - 模板测试

2. **不适合缓存的场景**
   - 需要实时最新结果
   - 输入频繁变化
   - 随机性要求高

3. **缓存管理建议**
   - 定期清理缓存（一周一次）
   - 注意缓存大小限制
   - 调试完成后考虑禁用

## 🔧 故障排除

### Vision 节点问题

**问题：图片无法识别**
- 检查图片 URL 是否可访问
- 确认图片格式支持（JPG, PNG, WebP）
- 检查 API Key 是否配置正确

**问题：识别结果不准确**
- 尝试调整 temperature 参数（降低到 0.3-0.5）
- 优化提示词，提供更多上下文
- 更换更强大的模型（如 GPT-4o）

### OCR 节点问题

**问题：文字识别错误率高**
- 提高图片清晰度
- 选择专业 OCR 服务（百度）
- 后接 LLM 节点进行纠错

**问题：识别速度慢**
- 启用缓存功能
- 使用较小的图片
- 选择响应更快的服务商

### 缓存问题

**问题：缓存未生效**
- 检查 `enableCache` 选项是否开启
- 确认浏览器支持 IndexedDB
- 查看浏览器控制台错误信息

**问题：缓存占用空间过大**
- 手动清理缓存
- 调整 `MAX_CACHE_SIZE` 配置
- 缩短缓存过期时间
